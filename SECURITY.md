# Security policy

## Supported version

Security fixes are applied to the current `main` branch and latest release.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, leaked credential,
privacy exposure, or abuse path. Use GitHub's **Security → Report a
vulnerability** flow after private vulnerability reporting is enabled for
the repository.

Include the affected route or component, reproduction steps, expected
impact, and any suggested mitigation. Do not include real user data or
actively exploit a production system.

If GitHub private vulnerability reporting has not yet been enabled, keep the
report private and contact the repository owner directly through a verified
channel. The owner should add a dedicated security contact before inviting
external contributors.
